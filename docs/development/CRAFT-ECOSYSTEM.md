# Craft ecosystem and dependency assessment

**Reviewed** 2026-11-24 · **Status** Source and documentation review for [ADR-012](../requirements/26-adr-012-egui-craft-ui.md)

## Source identity and version constraints

The relevant upstream is `storytold/craft-libs`, used by the Storytold Craft applications. The inspected revision [`249a41b`](https://github.com/storytold/craft-libs/commit/249a41bd9306a1b34330ac94e596a1a8b881378a), dated 2026-11-23, declares Rust 1.95, egui 0.37 and `MIT OR Apache-2.0`. Its workspace patches egui to a Storytold fork. The separate registry package `craft-ui` 1.4.7 points to `aphrody-labs/craft-libs`, a fork of Storytold's repo. Its manifest declares Rust 1.97 and egui 0.36.2. Cargo package names alone are insufficient to establish dependency identity. [Inspected upstream manifest](https://raw.githubusercontent.com/storytold/craft-libs/249a41bd9306a1b34330ac94e596a1a8b881378a/Cargo.toml) · [Registry manifest](https://docs.rs/crate/craft-ui/1.4.7/source/Cargo.toml) · [Fork metadata](https://api.github.com/repos/aphrody-labs/craft-libs)

Upstream egui 0.37.0 also declares Rust 1.95. CANexus pins Rust 1.92 and CI repeats the version. Start with an isolated Rust 1.95 evaluation using crates.io egui/eframe 0.37 and the exact Storytold Craft revision. Check the build graph and APIs before selecting a version. If a fork-only API is required, record the exact missing API and test a complete, consistently pinned family as a second experiment. The application's workspace owns the patch resolution. A dependency's own workspace patch or lockfile does not settle it for CANexus. [egui 0.37 manifest](https://raw.githubusercontent.com/emilk/egui/0.37.0/Cargo.toml) · [VectorCraft dependency history](https://github.com/storytold/vectorcraft/blob/main/docs/egui-037-migration-plan.md)

Before dependency promotion, capture `cargo metadata --locked`, `cargo tree -d`, the feature and target graph, and release build sizes for Windows and Linux. Inspect active versions and source IDs for egui, eframe, epaint, emath, renderer, AccessKit, winit and test crates. Pin and commit the application lockfile at cutover and run locked builds on both platforms. Check the selected revision's actual licenses, optional code, font/icon assets, bundled material and native system dependencies. Preserve required third-party notices and review upstream terms before distributing binaries or assets. The repository's MIT license and upstream dual licensing are the starting points for that assessment. [Craft copyright and notices](https://github.com/storytold/craft-libs/blob/main/NOTICE) · [Craft attribution](https://github.com/storytold/craft-libs/blob/main/ATTRIBUTION.md) · [License rules](https://github.com/storytold/craft-contrib/blob/main/standards/licences.md)

## Contribution and community path

- **Contribute upstream** when DEV-024/022 uncovers a reproducible generic defect in docking geometry, keyboard reachability, focus restore, accessible controls or screenshot fixtures. Prepare a small demo with synthetic values, accessibly named controls, exact revisions and independent Windows/Linux test evidence. Favor a source-level fix in the shared project after maintainer review. Track any temporary patch with a removal condition.
- The public `craft-contrib` rules identify maintainers and owners, and document an RFC path. Adding/removing an app is described as a larger decision with a usual seven-day comment period. This is evidence of a possible route. Evaluate recent accepted RFC precedent, contributor/license requirements and maintainer expectations before proposing affiliation. [Craft contribution guide](https://github.com/storytold/craft-contrib/blob/main/README.md) · [Decision process](https://github.com/storytold/craft-contrib/blob/main/rfcs/0000-decision-process.md)
- DEV-027 prepares CANexus for independent contributions first. Produce a verified build guide, synthetic examples, contributor workflow, release/triage ownership, dependency and asset inventory, and a generic component contribution list. Maintain standalone build/test and local project ownership. A formal proposal, external contact or transfer requires a separate owner decision.
